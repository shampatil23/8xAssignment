---

#### 2. `accounts:signUp 400 (Bad Request)` at `auth.ts:50`
* **What Happened:**
  1. Your initial registration for `sham1@gmail.com` **actually succeeded** and created your profile in Firebase Realtime Database:
     ```json
     {
       "displayName": "sham",
       "email": "sham1@gmail.com",
       "role": "customer",
       "accountStatus": "active"
     }
     ```
  2. However, the Edge middleware was checking `request.cookies` for `firebase:authUser:`. Because Firebase Client SDK stores tokens in **`IndexedDB`** rather than HTTP cookies, the middleware saw an empty cookie and responded with a `307 Redirect` to `/auth/sign-in?redirect=/account`.
  3. Re-submitting the registration form with `sham1@gmail.com` caused Google Identity Toolkit to return **HTTP 400 Bad Request (`EMAIL_EXISTS`)** because the account was already created on the first attempt.

* **Fixes Implemented:**
  1. **[middleware.ts](file:///c:/Users/bavis/Downloads/AmazonClone/amazonclone-app/src/middleware.ts):** Removed false route redirects so that [AuthGuard.tsx](file:///c:/Users/bavis/Downloads/AmazonClone/amazonclone-app/src/components/auth/AuthGuard.tsx) manages client-side authentication and role-based access directly from Firebase's persistent `IndexedDB` state.
  2. **[AuthContext.tsx](file:///c:/Users/bavis/Downloads/AmazonClone/amazonclone-app/src/context/AuthContext.tsx) & [authService.ts](file:///c:/Users/bavis/Downloads/AmazonClone/amazonclone-app/src/services/authService.ts):** Automatically synchronizes a client-session cookie (`auth_session=1`) upon login and registration, and clears it on sign-out.
  3. **Verification:** TypeScript compilation verified with `npx tsc --noEmit` (0 errors) and Next.js dev server running cleanly.
